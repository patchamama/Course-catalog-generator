## Internal Reference Updates Applied

The following internal references were updated automatically during the migration:

### `deploy/start.py`
- `VENV_DIR` now points to `ROOT_DIR / '.venv'` (was `SCRIPT_DIR / '.venv'`)
- `REQ_FILE` → `BACKEND_DIR / 'requirements.txt'`
- `env.py` → `BACKEND_DIR / 'env.py'`
- `ollama_setup.py` → `BACKEND_DIR / 'ai_ollama_setup.py'`
- `catalog_generator.py` → `BACKEND_DIR / 'catalog_generator.py'`
- `catalog_server.py` → `BACKEND_DIR / 'catalog_server.py'`
- Catalog output dir → `ROOT_DIR / 'output'`

### `deploy/setup-dev.py`
- Same VENV/BACKEND_DIR pattern as `start.py`
- `ES_TEST_HTML` → `ROOT_DIR / 'frontend' / 'search-console.html'`
- `COMPOSE_FILE` stays in `SCRIPT_DIR` (deploy/)
- `es_indexer.py` → `BACKEND_DIR / 'search_indexer.py'`
- `es_status.py` → `BACKEND_DIR / 'search_status.py'`
- `catalog_server.py` → `BACKEND_DIR / 'catalog_server.py'`
- `env.py` → `BACKEND_DIR / 'env.py'`
- `default_test` → `ROOT_DIR.parent / 'test'` (preserved original behavior)

### `deploy/Dockerfile`
- `COPY requirements.txt` → `COPY backend/requirements.txt`
- `COPY catalog_server.py es_indexer.py` → `COPY backend/catalog_server.py backend/search_indexer.py`
- `COPY env_docker.py ./env.py` → `COPY backend/env_docker.py ./env.py`
- `build: .` → `build: ..` (in docker-compose.yml)

### `backend/catalog_server.py`
- `es_indexer.py` references in subprocess calls → `search_indexer.py`

### `backend/search_indexer.py`
- `from translation_worker import TranslationWorker` → `from ai_translation import TranslationWorker` *(was a runtime import bug)*

### `frontend/search-console.html` and `frontend/chat.html`
- Home link `href="index.html"` → `href="../index.html"`

### `index.html`
- Tool card links updated to `frontend/search-console.html` and `frontend/chat.html`
